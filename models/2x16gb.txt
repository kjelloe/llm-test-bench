# Hardware notes for this pair, all confirmed on card #1 (2026-09-16):
# - Blackwell sm_120. MXFP4 models are fine (they need Ampere+, this is newer).
# - PCIe gen 5 but the slot reports **x8**, and the second card lands on a bifurcated x8. Every
#   token's layers cross that link with tensor_split, so it is the main unknown for speed here.
#   Check under load: nvidia-smi --query-gpu=index,pcie.link.gen.current,pcie.link.width.current --format=csv
# - No NVLink.
# - **Windows holds ~1.1 GiB of whichever card drives the display**, invisible to nvidia-smi inside
#   WSL (card #1 shows 14.8 of 15.93 GiB free). tensor_split=1|1 splits evenly and can therefore OOM
#   on the display card first. If that happens, shave that card's share (e.g. tensor_split=0.93|1)
#   or drop max_ctx — untested, but the arithmetic is simple.
# - llama.cpp pinned at 67a17c17c (~/GIT/llama.cpp), which still accepts --no-mmap. A build past
#   14a9d09f7 removes it; the harness translates no_mmap to --load-mode none automatically
#   (lib/llama_server_client.py), so these entries need no edit on a rebuild.
# - llama-server is NOT on PATH on this box; run with
#   LLAMA_SERVER_BIN=~/GIT/llama.cpp/build/bin/llama-server
# - **Model location matters.** $LLAMA_MODELS_DIR defaults to ~/GIT/ollama-code-bench/llama_models,
#   which is a symlink to /mnt/c/GIT/llm-test-bench — i.e. the Windows drive over 9p, ~190 MB/s. A
#   17 GB model takes ~90 s to load from there every start. Copy the ones you use to ~/models
#   (WSL ext4) and set LLAMA_MODELS_DIR=~/models. Already on /mnt/c (2026-09-16): qwen3.5:27b,
#   qwen3.6:27b, qwen2.5-coder:32b-q4, devstral-small-2, qwen3.8-27b-gsqrco.
#
# VRAM budget: keep weights + KV under ~29 GB of the 32, leaving room for compute buffers and the
