# ── CPU-MoE paging technique (llama-server) ──────────────────────────────────
# For MoE models that are slightly over VRAM capacity:
#   -ngl 999 --n-cpu-moe N --no-repack
# Keeps MoE expert tensors of the first N layers on CPU (mmap'd from file, page-cached in RAM).
# Attention + non-overridden layers stay on GPU. Only the active experts need to be RAM-resident.
# MUST NOT use: --no-mmap / --mlock (forces full RAM residency, defeating the purpose).
# So model entries using this technique MUST omit no_mmap from their param string.
# Speed: gated by DDR5 bandwidth through the active-expert working set.
#   At 90 GB/s DDR5: ~3B active params at Q4_K_M ≈ 1.7 GB/tok → ~53 tok/s
#                    ~15B active params at Q5_0 ≈ 9.4 GB/tok → ~10 tok/s (borderline for bench)
# Best use case on this hardware: models ≤3–4 GB over the 72 GB VRAM limit —
#   a small n_cpu_moe value (4–8 layers) sheds just enough expert weight to fit,
#   leaving throughput near GPU speeds.
# Dense models gain nothing — all weights touched every token = disk thrash.
